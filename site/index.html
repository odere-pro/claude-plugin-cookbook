What's inside

A reference and a working starter

This repository is both a reference cookbook for building Claude Code plugins and the installable plugin-cookbook plugin itself — whose new-plugin skill scaffolds a new plugin from the skeleton.

15-chapter reference

docs/cookbook/ documents one attribute per chapter — manifest, skills, commands, subagents, hooks, rules, MCP, validation, distribution, supply-chain governance, and repository hygiene.

Validated skeleton

skeleton/ is a minimal, valid, loadable plugin that already passes claude plugin validate --strict. Copy it — don't start from scratch.

BOOTSTRAP playbook

docs/cookbook/BOOTSTRAP.md is an agent-followable playbook that turns a plain repo into a well-formed plugin, step by step.

The new-plugin skill

/plugin-cookbook:new-plugin copies the skeleton, fills the manifest, runs strict validation, and initializes a clean git history — scaffolding for you.

CI gates

tests/gates/run-all.sh ships standalone checks that enforce the well-formed-plugin invariants — JSON, strict validation, links, secrets, local-only hooks, changelog.

Governance, pre-wired

Conventional Commits, per-PR changelog fragments, CodeQL, and an OpenSSF Scorecard — supply-chain and repository hygiene built in from chapter 13–14.

How it works

Copy a validated starter, then ship

One mental model drives everything: descriptions are always-on, bodies load on invoke. You copy a starter that already validates, fill in the blanks one attribute at a time, keep it strict-clean, and ship it to a marketplace as a versioned release.

Three ways to use it, from most hands-on to fully delegated — the same skeleton is the spine of each:

  1. Copy — cp -R skeleton/ ../my-plugin, then follow BOOTSTRAP.md and run claude plugin validate . --strict yourself.
  2. Template — click Use this template on GitHub, keep the contents of skeleton/ at the root, and delete docs/.
  3. Ship with Claude — install the plugin and run /plugin-cookbook:new-plugin my-plugin to scaffold, validate, and init in one step.

Get started

Scaffold in three commands

# In a Claude Code session — add the marketplace, then install
/plugin marketplace add odere-pro/claude-plugin-cookbook
/plugin install plugin-cookbook@plugin-cookbook

# Scaffold a new, already-valid plugin into ./my-plugin
/plugin-cookbook:new-plugin my-plugin
It scaffolds, it doesn't touch your repo. /plugin-cookbook:new-plugin copies the validated skeleton into a new ./my-plugin directory, fills in the manifest, runs claude plugin validate --strict, and initializes a clean git history. The skill is disable-model-invocation — it runs only when you invoke it by name. 
# Prefer to drive it by hand? Copy the starter and validate
cp -R skeleton/ ../my-plugin && cd ../my-plugin
claude plugin validate . --strict

# Develop this repo
bun install
bun run lint:md && bun run format:check   # markdown lint + prettier
bash tests/gates/run-all.sh               # the full gate suite

Questions

Frequently asked questions

What is the Claude Plugin Cookbook?
It is both a reference and a working installable plugin for Claude Code. The cookbook is a 15-chapter reference that documents the whole plugin contract — manifest, skills, commands, subagents, hooks, rules, MCP, validation, distribution, and repository hygiene — and it ships a validated starter skeleton plus the /plugin-cookbook:new-plugin skill that scaffolds a new plugin from that skeleton.
Do I need to read the whole cookbook before building a plugin?
No. Start with the one mental model in the overview, then either copy skeleton/ and follow the BOOTSTRAP playbook, or install the plugin and run /plugin-cookbook:new-plugin. The 15 chapters are a reference you cite one attribute at a time — not a linear book you must finish first.
Does /plugin-cookbook:new-plugin change my repository?
No. It copies the validated skeleton into a new directory you name (for example ./my-plugin), fills in that plugin's manifest, runs claude plugin validate --strict, and initializes a clean git history inside the new directory. It does not modify the repository you invoke it from.
How is a plugin validated?
Both the cookbook's root plugin and the skeleton stay claude plugin validate --strict-clean. On top of the built-in validator, the repo ships standalone CI gates (tests/gates/run-all.sh) that check JSON parses, strict plugin validation, shell linting, no absolute machine paths, valid doc links, markdown style, secret scanning, local-only hooks, and changelog/glossary consistency.
Can I use the cookbook as a GitHub template instead?
Yes. The repository is a GitHub template — click Use this template to get a new repo with the same baseline, then keep the contents of skeleton/ at the root and delete docs/. The skeleton already ships a badged README, a CHANGELOG.md, a CONTRIBUTING.md, and the lint/format/editor config.
Will the plugin cost context when I'm not using it?
The new-plugin skill is side-effecting, so it is disable-model-invocation — it costs no standing context and only runs when you invoke it by name. The cookbook reference is documentation in the repo, not loaded into every session.
